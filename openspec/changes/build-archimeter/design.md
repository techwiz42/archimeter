## Context

Greenfield repo. Brief requires a design proposal and **user confirmation before any code is written**; this document is that proposal. The tool analyzes untrusted targets statically. Intended real-world targets: a composed source project, and applications generated by a module-composing code generator.

The project's no-fakes rule applies to the tool itself: no fake data or fallbacks in product code. The user's brief explicitly requires small fixtures and mocked GitHub/registry APIs *in tests*; that is the explicit permission, and mocks stay under `tests/`.

## Goals / Non-Goals

**Goals:** all requirements in `specs/`; one extractor = one file; read-only and static; works with zero config.
**Non-Goals:** building/running targets or containers; Docker daemon; analyzing third-party package code (inventory only); GitHub Enterprise Server (open question); writing a provenance emitter in any generator (separate change).

## Decisions

**D1 Extractor interface.** `class Extractor(Protocol)`: `name`, `applies(target) -> bool`, `extract(ctx: Context, sink: GraphSink) -> None`. Registered via `archimeter.extractors` entry-point group plus built-ins in `archimeter/extractors/`. `Context` exposes file tree, config, git handle, parsed-file cache. Order is declared via `requires = ("modules",)` and topologically sorted (events need module map; provenance needs everything). Alt: inheritance base class — rejected, Protocol keeps plugins light.

**D2 Graph model.** `Node(id, level, parent, attrs, provenance)`, `Edge(src, dst, kind, weight, evidence)`; ids are level-prefixed paths. Edges stored at the finest level they were observed, rolled up by aggregation to module/package/service. Stored as `networkx.MultiDiGraph`; `GraphAlgo` protocol (`scc`, `closure_matrix`, `components`) with `NetworkxAlgo`. Propagation cost uses `scipy.sparse` boolean matrices with repeated squaring, not `nx.transitive_closure`, for thousands of nodes. Alt: igraph now — deferred, keeps install simple.

**D3 Module boundaries.** Detection order: config `modules` → Python top-level packages (dirs with `__init__.py` or namespace dirs under `src/`) → JS/TS `package.json` workspaces/nearest package.json → top-level `src/*` dirs → top-level dirs. Config can `group`, `rename`, `exclude`. Detected boundaries are written into `metrics.json` so they're auditable.

**D4 GitHub auth.** Resolver chain in `auth/sources.py`: env → keyring → `gh auth token` (subprocess, no shell) → device flow. Device flow: POST `github.com/login/device/code` with configured `client_id` and scopes, poll `login/oauth/access_token` honoring `interval` and `slow_down`. Scopes: OAuth Apps cannot be repo-read-only; the narrowest classic scope is `repo` for private repos (documented limitation) — fine-grained PAT (Contents: read, Metadata: read) is the true least-privilege path and is recommended in README; `read:packages` added only for ghcr.io. Tokens: `keyring` only (service `archimeter`, user `github`); on headless systems with no keyring backend, fail loudly with guidance (no plaintext file fallback). Git receives the token via `-c http.extraHeader="Authorization: Basic …"` on the single command (never in URL, never in config). A `Redactor` filter wraps logging and exception formatting, seeded with every known secret in-process.

**D5 Images without a runtime.** Pure-Python OCI client on `httpx`: token-challenge auth, manifest/index resolution (platform default `linux/amd64`, configurable), blob fetch with digest verification, cache in `~/.cache/archimeter/images/sha256/…`. Credentials from Docker `config.json` (`auths`, `credsStore`, `credHelpers` — helper invoked as `docker-credential-*` get; that is executing a *user-installed* helper, not target code). Tarballs: `docker save` (manifest.json) and OCI layout (index.json) parsed directly. Alt: shell out to `crane`/`skopeo` — rejected as extra install dependency; may be reconsidered.

**D6 Safe unpack.** Custom tar walker over `tarfile` streaming, never `extractall`: per member validate normalized path under root, reject absolute/`..`, device/fifo, hardlinks escaping root; symlinks stored only if target resolves inside root, and writes through symlinked dirs are re-resolved with `Path.resolve()` checks; whiteouts (`.wh.*`, `.wh..wh..opq`) applied; running byte and file-count caps (configurable); decompression-bomb guard on gzip/zstd by counting output bytes. Permissions bits stripped (no setuid).

**D7 App vs third-party separation.** Signals in priority order: config paths → image `WorkingDir`/entrypoint script location → directories containing the entrypoint module → everything not under OS dirs (`/usr`, `/lib`, `/etc`, `/var`, `/opt` non-app, `/bin`) and not under `site-packages`/`dist-packages`/`node_modules`. Third-party inventory from `*.dist-info/METADATA`, `package.json`, `package-lock.json`, `poetry.lock`, `requirements*.txt`, `yarn.lock`. Each decision logs its evidence; ambiguity (multiple candidate roots, no entrypoint) is reported under `uncertainty`.

**D8 Provenance.** Manifest (JSON, documented in README): `{ "format": "archimeter-provenance/1", "files": { "<path>": { "module": "...", "template": "...", "version": "...", "kind": "copied|rendered|generated" } } }`. Fallback matching: sha256 of normalized content → `copied`; else AST similarity = normalized tree-edit proxy (Jaccard over node-type n-gram shingles, deterministic, default threshold 0.6) against framework files of the same language → `modified`; else `new`. Ties → unattributed. Framework index built once and cached by framework SHA.

**D9 Event presets (shipped).** redis (`publish`/`xadd`; `subscribe`/`psubscribe`/`xread`/`xreadgroup`; channel arg 0), celery (`@task`/`@shared_task` definition as subscriber, `.delay/.apply_async/send_task` as publisher), django-signals (`Signal()` definitions, `.send/.send_robust`, `.connect`/`@receiver`), blinker (`signal(name)`, `.send`, `.connect`/`.connect_via`), kafka (`producer.send/produce`, `consumer.subscribe`, `KafkaConsumer(topic…)`, kafkajs `send({topic})`/`subscribe({topic})`), node-eventemitter (`emit`/`on|once|addListener`, string-literal names). Presets are data (TOML tables of call names, arg index/keyword, receiver hints), so custom patterns use the same schema. Name resolver does intra-file constants, cross-file imported constants (via the import graph) and enum members; everything else → `unresolved`.

**D10 Cognitive complexity.** `complexipy` (Rust, fast, implements SonarSource cognitive complexity; maintained pip wheels). Alt: `cognitive_complexity` package — slower, less maintained.

**D11 Libraries.** typer (CLI), networkx (+scipy sparse) (graph), radon + lizard (metrics), complexipy, tree-sitter with `tree-sitter-javascript`/`-typescript` wheels (parsing), httpx (registry/GitHub APIs), keyring, PyYAML safe_load (compose/k8s; `yaml.safe_load` only), tomllib/tomli-w (config), jinja2 (report template; plain-data JSON embedded in HTML), D3 and a heatmap lib from cdnjs/jsdelivr pinned with SRI hashes, pytest + respx (HTTP mocks, tests only).

**D12 Change history.** `git log --name-status --no-renames`-style streaming parse via `git` subprocess with blobless clone (no blobs needed for names); renames followed with `-M` for churn continuity. Coupling: per-commit module set, pair support, confidence = support / commits(a) (directional, both reported). Hidden coupling = support ≥ min_support and confidence ≥ min_conf and no import/event edge either direction. Trend uses `git worktree add --detach` into a temp dir under cache from a *private* clone (never the user's repo), blobs fetched on demand.

**D13 Report.** One Jinja template emits a single HTML with a JSON data island; client-side rendering. Size budget enforced; large graphs are pre-aggregated to module level with drill-down lazily expanding from embedded data.

**D14 Repo layout.** `src/archimeter/{cli.py, config.py, resolve/, auth/, images/, extractors/, graph/, metrics/, report/, compare.py, trend.py}`, `tests/`, `docs/provenance-format.md`.

## Risks / Trade-offs

- [OAuth device flow cannot do read-only repo scope] → Document; recommend fine-grained PAT; state plainly in `auth login` output.
- [Event resolution misses dynamic names] → Reported as unresolved, never guessed; count shown in summary.
- [App/third-party separation wrong for odd images] → Evidence + `uncertainty` section; config override.
- [Zip/tar bombs, symlink escapes] → D6 plus dedicated hostile fixtures.
- [AST similarity threshold arbitrary] → Configurable; fixture-calibrated; distribution reported.
- [Marginal complexity from few configs is statistically weak] → Low-confidence labeling; method documented (least-squares of metric on module-inclusion indicators, ridge-regularized; exact difference when configs differ by one module).
- [Keyring unavailable on servers] → Fail with instructions to use env token; no plaintext store.
- [Performance for 100k LOC] → Process pool for parsing, parsed-file cache, sparse matrices; benchmark in test suite.

## Migration Plan

Greenfield; nothing to migrate. Delivered incrementally: M1 skeleton/graph/Python imports/metrics/JSON → M2 JS/TS, events, git → M3 report → M4 auth/clone → M5 images/service/provenance → M6 compare/trend → M7 real-target runs. Rollback is not applicable (new repo).

## Open Questions

Resolved with the user:

- **Registry client:** pure-Python (D5).
- **Repository:** public. Nothing private (deployment contents, hostnames, secrets, internal names) may appear in code, fixtures, docs, results or specs; fixtures are synthetic and published results are anonymized.
- **Targets:** the generator's source is a private GitHub repository, reachable here through an authenticated `gh` session, so the `gh auth token` source in the credential chain covers private access. Generated applications are build-output directories (Dockerfiles, compose file, source), not images.
- **Provenance manifest:** v1 reads one if present and otherwise uses `--framework` matching. Emitting a manifest is not part of this change.
- **Scopes / OAuth client ID:** needed only for other users' private repos. The device flow is shipped, configured by a client ID in config; it is verified by mocked-API tests only.
- **Defaults chosen:** hashed author emails; no GitHub Enterprise in v1.

Remaining notes:

1. Real deployments contain secret and database directories: the denylist must keep them unread (tested with synthetic equivalents).
2. Registry-image verification uses a small public image; tarball verification uses synthetic fixtures.

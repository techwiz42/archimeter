# First results (anonymized)

Produced with archimeter 0.1.0 on two applications generated by a module-composing code generator, with `--framework` pointing at the generator's source. The applications and the framework are private, so **names are pseudonymized**: modules are `modules/mNN`, events are `event-NNNN`, files are `src/file-NNNNN.ext`, and the generator's own module is `generator`. Pseudonyms are consistent across every file here; code snippets, environment variable names, configuration and author data were dropped. The numbers are unchanged.

Open the `report.html` / `compare.html` files in a browser (they load D3 from cdnjs).

* `single-application/` : `archimeter analyze <app-b> --config <event-bus config> --framework <framework source>`.
* `compare/` : `archimeter compare <app-a> <app-b> --config ... --framework ...`, with one subdirectory per application.

## app-b (the larger application)

242k lines, 1,574 files, 26 modules.

* Propagation cost: 89% imports, 27% events, 56% across services. One 24-module dependency cycle with 32 direct two-way pairs; `backend` is the hub (removing it drops propagation cost by 37 points). Top two-way pairs: `core <-> modules/m18`, `backend <-> core`, `core <-> modules/m19`.
* Highest fan-in: `backend`, `core` and `modules/m03` (24 modules each).
* Events: 297; 86 published with no subscriber; 21 subscribed but never published; 114 sites with runtime-built names (unresolved, never guessed). One subscription uses a bare string that differs from the event's enum value, so it can never fire (`event-0002`).
* Hidden coupling: 13 pairs from the framework's own git history (the generated application has none), all involving `generator`.
* Shared-database coupling: none.
